## Context

Camera/microfoon-aanvragen van een P2P-peer moeten door dezelfde native
bevestigingsflow van de shell lopen als execute-skill, vault of
`peersite.requestAccess` — nooit een lichte browser-`getUserMedia`-popup.

## Besluiten

- **`p2p-hub:media:v1` wire-contract in de SDK** (`sdk/src/media-contract.ts`) —
  fail-closed parsing, canonieke bytes, **geen identity/token-velden op de wire**.
- **Sessielevenscyclus** in `plugins/media`: `requestSession`/`closeSession`/
  `getStreamStatus` met `kind: "camera"|"microphone"`; sessies per-request
  gegeneerd met `MediaGate` (via `checkPeerAccess`) én per-request
  `TelemetryGate`-frequentie-cap voor actieve sessies.
- **Alle sessions-skills `httpBridgeOnly: true`** (lokaal operatoroppervlak,
  structureel nooit peer-facing) + `localOnly: true`. De broker-`core.media.request`
  (in core-server) vereist een transport-verified `context.peerId`, gate elke grant
  door `confirmMediaRequest` (Tier-2 native confirm, fail-closed), `remote:
  { gate: "verified-contact" }`, niet HTTP-geëxposeerd, per-peer cooldown tegen
  prompt-spam.
- **Stream-transport blijft buiten scope** — een grant/sessie is het geverifieerde
  oordeel dat een toekomstig transport consumeert.
