## Context

Capability-gerichte Pub/Sub bovenop `network-light`, structureel klaar voor de
streaming-richting van A1-besluit 3 (hoogfrequente events vallen onder de
TelemetryGate, niet onder de broker-taak-limiter). Accordeerbare schikkingen: hub
in `core/src/events/`, per-topic-autorisatie uitsluitend via `manifest.exposedEvents`.

## Besluiten

- **Wire-frames** — `sub_req`/`sub_ack`/`event_emit` in de `p2p-hub:network`-
  envelop, elk alleen na geverifieerde `auth`; canonieke veldvolgorde + gepinde
  bytes; topic-vorm = hook-conventie `<ns>:<name>` met delimiter-geankerde
  wildcard `:*`.
- **Hub & adapter** (`core/src/events/`) — `SubscriptionHub` (remote-subscriptions
  naar ons) + `RemoteEventAdapter` (local-subscriptions naar remote), beide achter
  één `EventNetwork`-interface, duck-typed op de actieve provider.
- **Per-topic-autorisatie = `exposedEvents`-only** — remote-subscribable alleen bij
  **exact-match**; alles anders default-deny (`topic-not-exposed`). `checkPeerAccess`
  is de peer-level laag eronder (default `["open-lan"]`).
- **`event_emit` door `TelemetryGate` per (peer, topic), aan beide kanten** —
  receiver-side bij inbound-dispatch, sender-side in `emitLocal` vóór de
  wire-send (een hete publisher-topic overspoelt een peer ook op de draad niet).
  Overflow **dropt** (spamt/sluit nooit; dropped frame verhoogt de
  per-subscription `sequenceNumber` niet).
- **`publisherPeerId` is nooit een vertrouwd loose field** — transport-level
  afgedwongen: provider sluit bij mismatch met de authenticated connection-peerId;
  adapter her-checkt (defense-in-depth). V1 = direct publisher→subscriber,
  **géén relay**.
- **Caps + TTL-bounds** — `MAX_SUBSCRIPTIONS_PER_PEER` (64),
  `MAX_SUBSCRIPTIONS_PER_TOPIC` (128), `ttlMs` gecapt (5 min, default 60s).
- **`ctx.events`** — `publishRemote`/`subscribeRemote`/`unsubscribeRemote`;
  namespace-gebonden (eigen `<pluginId>:`-prefix); lazy layer-build; sandbox-`ctx`
  heeft een fail-closed events-stub.
