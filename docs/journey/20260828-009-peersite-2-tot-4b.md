## Context

PeerSite is de eerste *peer-app*: een peer deelt een lokale directory. Vroeg
prototype van het capability-model dat later door Fase 2A platform-afgedwongen
werd.

## Besluiten

- **Scoped PeerSite API + LAN opt-in** (`369899d`) — site-mirroring begint
  HTTP-scoped; de P2P-kant bouwt erop voort.
- **`ctx.trust` capability** (`ad51482`, seam `58bd274`) — in-process contact
  trust-lookup zodat het platform de trustlaag levert i.p.v. de plugin.
- **Inbound peer-auth** — challenge-response proof-of-possession
  (`p2p-hub:peersite:auth:v1:`) over de bestaande TLS-sessie, gated op
  `ctx.trust.getContact` (verified-contact-only). Geen `rejectUnauthorized: false`;
  een latere hardening kan de transport-cert-fingerprint aan het contact pinnen.
- **Shared site containment** (`f9cc342`) — `resolveAndContainFile`-containment en
  atomic-writes voor de gemirrorde site (later gecentraliseerd in 008).
- **ENS als naming-adapter** (`64a2138`, Fase 4A) — ENS-name-resolution koppelt aan
  de geverifieerde peer-identiteit; ENS blijft een losse resolver/discovery-adapter
  (plan.md: "wie/waar moet ik zoeken?"), geen onderdeel van het transport.
- **Access passes met native confirm** (`71f2d37`, Fase 4B) — peer access passes
  worden via de native bevestigingsflow van de shell verleend (Tier-2-gedrag) en
  later in `AccessPassManager`/`ctx.access` gecentraliseerd (005).
